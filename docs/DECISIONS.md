| 2026-10-21 | Analysis libraries go in a uv dependency group `analysis`, not the main dependencies. | Keeps the scraper's Docker image small; `uv run --group analysis` for all analysis work. |
| 2026-10-21 | Canonical season key `"2014-15"`; date-based season runs 1 July to 30 June (`analysis.load.season_key`, `season_from_date`). | Plan, Phase 1. Already used in the Phase 0 audit. TM `seasonId` agrees with the date season for 98.3% of in-window injuries. |
| 2026-10-21 | An injury event is `playerId + start + end + label`, not `injuryId`. | `injuryId` turned out to be an injury-type code shared across players. |
| 2026-10-21 | Several diagnoses on the same absence (same player + start date; 205 absences, 427 records in window) are **counted as separate injuries**. | User's choice. Each record keeps its own label, body area and duration. Inflates counts by about 220 events (0.3%); exact repeats (same player + dates + label) are still dropped. |
| 2026-10-21 | Phase 5 cluster comparisons use **league-adjusted rates** (player-season rate ÷ its league's average over all 12 seasons) as the primary measure. Raw rates are still reported, and within-league breakdowns serve as a check. | TM records far more injuries in some leagues (per played player-season: Bundesliga 1.86 vs Ligue 1 0.72), so clusters with many Bundesliga teams would look injury-prone because of the league mix. Adjusting per league removes that but keeps season trends. It doesn't fix recording jumps within a league (Premier League 2018-19). |
| 2026-10-21 | Repository restructured: `scraper/` (collection), `analysis/` (was `src/`, with its own `config.py`), `docs/`, `mappings/`. Analysis output goes to one folder per phase, `data/01_entities/` … `data/05_injury_analysis/`, replacing `data/interim/` and `data/processed/`. Hand-reviewed CSVs (`team_map`, `injury_label_map`) go to `mappings/` instead of `data/interim/`. | User's choice: clearer what each folder holds and easier to extend. Hand-made mappings are decisions that code can't regenerate, so they are tracked in git; `data/` is not. No effect on results. |
| 2026-10-21 | Team matching: per league-season, exact name, then equal after normalising (only when unambiguous), then fuzzy (mean of rapidfuzz token-set and token-sort ratios) with one-to-one Hungarian assignment. Verified on fixtures: each Football-Data and Understat league match must exist in TM fixtures with the same home and away club. Rows with name score < 75 are listed for review. | Plan, Phase 1. Token-set alone mapped PSG to "Paris FC" (a name contained in a longer one scores 100), hence exact-first and the stricter score. Fixtures are independent of names: 21,589 of 21,589 matches found in both sources. |
| 2026-10-21 | Parma keeps two rows in `mappings/team_map.csv` (Understat ids 204 for 2014-15 and 230 from 2018-19), both mapped to TM club 130. | Parma was refounded after its 2015 bankruptcy; Understat uses a new id, TM keeps one club. |
| 2026-10-21 | The 4 awarded results (score on the pitch vs awarded score differ between sources) are left as they are. | They don't affect the mapping. Style features in Phase 3 come from the match statistics, not the result. |
| 2026-10-21 | Each club has one name everywhere: `club`, Transfermarkt's name (e.g. "1.FC Köln", not also "FC Cologne"). Football-Data and Understat names stay in `team_map.csv` only as join keys. The 8 review rows were confirmed correct. | User's choice. TM is the master key, so its name is the natural single label for tables and charts. |
| 2026-10-21 | Each phase's steps live in its notebook, in order: a note (what and why), the code, and a check cell with the intermediate result. `analysis/` keeps only code shared across phases (`config`, `load`, `report`); `analysis/entities.py` was moved into `notebooks/01_entities.ipynb`. Replaces "thin notebooks calling src/". | User's choice: to follow how each step contributes to the goal and to improve and debug steps in place. Outputs unchanged (team map and team-season table byte-identical). |
| 2026-10-21 | Scraper run-state files (`manifest.csv`, `status.json`, `last_run.json`, `smoke.json`) moved from loose files in `data/` to `data/scraper_run/`, for local and Docker runs alike. `data/` holds folders only. | User's choice: no loose files in `data/`. No effect on data or results; validation still reads all 27,197 manifest URLs. |
| 2026-10-21 | Injury duration = TM `days` = end − start (days from injury to return). Not the website's inclusive count (+1). | Checked on 400 players' matches: on the `end` date only 3.6% are still marked injured and 40% play, so `end` is the return date; end − start then matches the consensus definition (Fuller et al. 2006, days to return to full participation). |
| 2026-10-21 | Season of an injury: date rule (1 July – 30 June), except summer 2020: injuries up to the player's club's last 2019-20 match (any competition) stay in 2019-20. | User's choice. 2019-20 ran into July–August 2020 after the COVID restart; this keeps those weeks, including European games in August, with the season being played. |
| 2026-10-21 | Injuries without an end date are dropped (180 in the window). | User's choice: no estimated return exists (all say "Return unknown"), so their severity can't be measured. |
| 2026-10-21 | Each injury is tied to the club the player was at on its start date, from his per-match records (raw `performance-game`, read only; national-team games and "played for a different team" rows ignored): last club match on or before the date in the same season, else the first one after. Injuries while at a non-Big Five club are dropped (1,682 of 27,515 > 7 days, 6.1%). | User's choice after seeing the numbers. They can't be linked to a Big Five team's style. Settles open decision 3. |
| 2026-10-21 | A Big Five player-season counts when the player has ≥ 1 appearance for that club in the season **or** is marked "injured" in ≥ 1 of its matches. Replaces "≥ 1 appearance" (open decision 2); the ≥ 900-minute sensitivity check stays. | User's choice. "≥ 1 appearance" alone drops 1,024 injuries > 7 days of 751 players who never got on the pitch, and they are the severe ones (median 52 days vs 24; 69% > 28 days), which would bias severity downward. |
| 2026-10-21 | Injury type (muscle, ligament, …) is not mapped; the label map has class, body area and a `surgery` flag (label describes an operation: surgery, arthroscopy, screw removal; body area kept when named). | User's choice. The question is about frequency, severity (days lost) and body area; type was 30% unknown and surgery is a procedure, not a type. Severity is unaffected. |
| 2026-10-21 | Label map reviewed: Knock = injury (body area unknown); Muscle fatigue = unspecified muscle (only > 7-day cases are analysed); Fitness and Rest = non-injuries; heart, appendix, dental, kidney, cancer, depression = medical conditions (excluded); inguinal hernia and pubalgia = groin injuries; inner/internal/collateral ligament without a joint = knee, outer ligament = unknown; ribs and abdomen = upper body. | User's review of the proposal, 2026-10-21. |
| 2026-10-21 | "Fitness" stays out of the injury count, separated from "Rest", and is analysed in Phase 5 as a **secondary outcome** (fitness absences per cluster, read mainly within the Bundesliga). Each non-injury carries `after_injury` (starts within 3 days after one of the player's injuries ended). | User's choice (option A). 70% of Fitness absences (664 of 953) are reconditioning right after an injury, and the Bundesliga records 10.9 per 100 player-club-seasons vs 0.4–1.1 elsewhere, so counting them as injuries would double-count and add league bias. As a separate outcome they can still show loss of stamina. |
| 2026-10-21 | Main injury definition stays **> 7 days**. Injuries of 4–7 days (**mild**, 5,180) are kept in `injuries_mild.parquet`; Phase 5 reruns the comparisons with > 3 days as a sensitivity check. | User's choice. 4–7 day injuries are recorded ~2.5× more often in the Bundesliga and Serie A than elsewhere (21.7 and 21.4 vs 8.4–9.9 per 100 player-seasons), so they add league-dependent recording noise; their share is stable over seasons (14–18%). |
| 2026-10-21 | Shots on target (for and against) are not clustering features. | User's question "do we need shooting stats at all?": they mostly measure team strength rather than style, are covered by npxG and deep completions (r = 0.88), and Football-Data's Serie A values are inflated in 2018-19 to 2020-21 (4.2–4.4 shots on target per npxG vs 3.0–3.8 elsewhere). Computed for the record only. |
| 2026-10-21 | Rest-day features leave out gaps of more than 21 days between a club's matches (369 gaps, 0.7%: winter break, COVID suspension, World Cup 2022 stop). International breaks stay in. | User's choice. Breaks are not match rest; with them, rest-day SD reached 39.9 days in 2019-20. |
| 2026-10-21 | Features are standardised over all team-seasons together (open decision 4). | Checked against the aim with the user: changes in style over seasons and differences between leagues must stay visible. Within-season scaling would give every season the same cluster mix by construction, so "cluster shares over time" would be flat. |
| 2026-10-21 | `rest_mean` dropped as redundant (r = −0.90 with `short_rest_share`, −0.89 with `matches_all`); `short_rest_share` kept. 16 features go into clustering. | Plan rule \|r\| > 0.9. Matches on < 4 days' rest are the congestion measure linked to injury risk (Dupont et al. 2010). |
| 2026-10-21 | New source step **Understat U2** (`getTeamData/{team}/{season}`): team-season statistics (attack speed, shot situations, formations, shot zones, …) collected for all 1,170 team-seasons (0 failures, 26 min), stored raw under `data/raw/understat/team/`, parsed to `us_team_stats`. Added to the scraper (collector, parser, validation) and the dashboard (U1/U2 steps on the Understat card, new tile and checklist item). | User's choice in Phase 4: the original features could not separate real playing styles (counter-attacking, set-piece reliance, back three). |
| 2026-10-21 | Clustering uses **style only**: workload (matches, European games, short rest, rotation) is not clustered but kept as exposure for Phase 5; npxG/npxGA are not clustered (open decision 5: style only). | User's choice. Workload follows team strength and the calendar, not how a team plays; with it, clusters mostly sorted teams by strength. |
| 2026-10-21 | New style features from Understat team statistics: fast-attack, slow-attack, conceded fast-attack, set-piece and outside-box shot shares, back-three minutes share. | They add the missing dimensions (counter-attacking, set pieces, back three); top team-seasons read like football (Leicester 15-16 counters, Man City slow build-up, Wolves/Torino back three). |
| 2026-10-21 | Clustering on **8 equal-weight style dimensions** (dominance, pressing, counter, high line, physical, set pieces, long shots, back three), each the mean of its features' signed z-scores, re-standardised. | User's choice. Six features measured dominance, so in raw form it counted six times and only k = 3–4 were stable. |
| 2026-10-21 | **k = 7 main, k = 4 robustness check.** Usable k = every cluster's bootstrap Jaccard ≥ 0.6 (Hennig 2007) and no cluster < 3%: k = 3, 4, 7. k = 7 Jaccard 0.61–0.84; k = 4 0.89–0.92. Names by rule (e.g. Back three = highest back-three score). | User's choice: k = 7 is expressive (Elite dominance, Controlled possession, Back three, Aggressive press and set pieces, Direct and physical, Counter-attacking, Passive low block); results that hold at k = 4 too are more credible. |
| 2026-10-21 | Phase 5 methods (defaults, for the user's review): unit = player-club-season; league-adjusted rate ratio by indirect standardisation (observed ÷ expected at the league's average), stricter version by league × age band × position; 95% CIs by bootstrap over team-seasons (1,000 resamples, seed 42); age on 1 January of the season in bands ≤21, 22–25, 26–29, 30+; team strength = thirds of points per match; congestion = thirds of short-rest share over player-seasons. | Descriptive methods within the course constraint (no regression). Bootstrapping team-seasons respects that players of one squad are not independent. |
| 2026-10-21 | Body-area differences between styles are only reported as style patterns when they hold **within leagues** (style's share relative to its league's share, above 1 in ≥ 4 of 5 leagues). | Leagues label injuries very differently (unspecified muscle 29% in La Liga vs 7% in the Premier League), so pooled differences partly reflect where a style is common. |
| 2026-10-21 | Phase 5 extension (evolution), methods: style cards from **core** team-seasons (distance to own centroid ≤ 80% of the distance to the next); eras 2014–18, 2018–22, 2022–26 (4 seasons each); trend shape from era means (rising / falling / peak / dip / flat, steps under 0.1 SD = flat); club style transitions between consecutive seasons; **Kitagawa decomposition** of the change in injury outcomes between eras into style mix and within-style parts (cells = league × style); style–injury links across the 60 league-seasons as within-league correlations, plus season-to-season changes to remove shared trends. | User's request: describe how styles evolved and how that relates to injury trends. All descriptive, within the course constraint. |
| 2026-10-21 | **Playing style per phase of play** (supersedes the 8-dimension, k = 7 clustering): attacking style from 4 attacking dimensions (possession, patience, verticality, directness) and defensive style from 4 defensive dimensions (press, high line, territory conceded, aggression), each clustered with K-means k = 4 (Ward compared); a team-season's style is the pair (13 combinations with ≥ 40 team-seasons, 38 team-seasons in rare ones). Names by rule from football-analysis vocabulary: Positional possession, Build-up into the box, Counter-attack, Direct play; High press high line, Compact mid-block, Aggressive duel press, Low block. Formation (back three ≥ 50% of minutes) is a structural descriptor, not clustered; fouls suffered left out. | User asked for more distinct, football-real styles. Literature describes styles per phase (Fernandez-Navarro et al. 2016: 8 attacking + 4 defensive styles; Demir et al.: clustering per phase; Plakias et al. 2025: possession vs counter-attack). Better separation (silhouette 0.21–0.22 vs 0.13) and stability (Jaccard 0.64–0.91); k = 3 loses the modern styles, k = 5 has dissolving clusters (0.53–0.55). Ward agrees only moderately (ARI 0.35–0.39): styles are a continuum. |
| 2026-10-21 | Phase 6: `reports/summary.md` is the course-report text (abstract, data, preprocessing, method, results, discussion, limitations, figures, references); `notebooks/06_report.ipynb` recomputes its headline numbers from the phase outputs and checks they match the text and that every cited figure exists. Mechanisms (sprints, contact) are stated as plausible readings, not findings, since no tracking data was used. | Plan, Phase 6. Keeps the report text tied to the reproducible analysis. |
| 2026-10-21 | Phase 6 adds an interactive results dashboard (Artifact, Dashboard type): cluster map per phase, style cards, style shares and dimensions over time with a league picker, rate ratios with CIs, attack × defence grid, body areas, season trend, decomposition and league stories. Every number comes from 10 JSON files exported by `06_report.ipynb` from the Phase 4–5 outputs (Phase 5 now saves its result tables). | User's request: a visual representation of the results, centred on the clusters. |
| 2026-10-21 | Phase 4 adds two clustering checks: a **Gaussian mixture model** per phase (k = 2…10, full covariance, seed 42; BIC prefers k = 2 in both phases) and a **consensus clustering** (co-association of 50 bootstrap K-means, 50 bootstrap GMM and Ward, average linkage, k = 4; ARI vs K-means 0.89 attack, 0.92 defence). K-means stays the main assignment. | User's request for further models that could improve results. Both are clustering (course constraint); they confirm the K-means styles and confirm that styles form a continuum. Deep clustering not used: 1,170 rows and 4 dimensions per phase give it nothing to learn. |
| 2026-10-21 | Membership strength = **fuzzy membership** (fuzzy c-means memberships from the K-means centroids, m = 2; Bezdek 1981), ≥ 0.5 in its own style = clear member (attack 703, defence 679 of 1,170). Replaces the distance rule (≤ 0.8) for style cards and the core-only check; second style and membership kept. GMM probability not used (its groups match K-means for only 60% of attacking team-seasons). | User's choice after comparing distance rule, fuzzy and GMM. Same clusters, graded instead of yes/no. Core-only RRs unchanged (Positional possession 1.25, high press 1.17). |
| 2026-10-21 | Result processing, fixed in advance: absolute excess injuries / days next to every RR; empirical-Bayes shrinkage (DerSimonian–Laird) of small-cell RRs (attack × defence grid, style within league); 3-season centred rolling means of the season series; body-area patterns tested within leagues (Cochran–Mantel–Haenszel) with **Benjamini–Hochberg FDR**, q < 0.05 = finding; RR by position and age band per style. | User's request: clearer results without overfitting. FDR outcome: 9 of 80 patterns survive (knee: aggressive duel press, counter-attack more; possession, high press fewer; low block fewer hamstring and groin); the hamstring/groin excess of possession and the high press is reported as a tendency only. Summary text updated. |
| 2026-10-21 | Results dashboard: clicking a style (legend, card, dot, cell) filters every card; position/age breakdown card; grid shows shrunk RRs; body areas mark FDR findings; season trend shows the rolling mean; cluster map shades dots by membership. | User's choices. |
| 2026-10-21 | Independent review of methods and code before the UI design (two reviewer agents, read-only). Adopted (user's choice): **nested expected values** (league × season main, + team strength, + age × position) and **two exposures** (per player-season, per team match); **bootstrap over clubs** with per-table seeds; Kitagawa cells **league × strength × style** with the strength mix separated; body areas by **permutation test** (team-season labels shuffled within league-season) with BH over 72 tests (formation tested once), MH odds ratio over league × era; sensitivity clusterings **k = 3** and **style relative to the league-season**; "≥ 1 appearance only" check; days lost with **overlapping absences merged**, capped and median versions; consensus described as stability summary, not validation. | The strength check compared strong possession teams with the whole league (A1); exposure ignored that strong teams play ~10 more matches (A2); the decomposition credited style with strength changes (A3); team-season bootstrap ignored repeated clubs; the per-injury CMH treated a squad's injuries as independent. Result: possession RR 1.21 → 1.09 after strength → 1.05 per match after strength; high press 1.14 → 1.05 → 1.02; body-area findings 9 → 2 of 72; attacking style mix +0.073 → +0.038 beyond strength. Summary text rewritten. |
| 2026-10-21 | Permutation test uses **10,000** shuffles (first run used 1,000). | With 72 BH tests the strongest pattern needs p < 0.05/72 ≈ 0.0007; 1,000 shuffles cannot give p below 0.001, so no pattern could pass. Changed for resolution, not for the outcome; documented here. |
| 2026-10-21 | Code restructure (planned, user's choice): steps become functions with structured checks and log rows (`analysis/phases/`), a runner writes `_run.json` per phase (hashes, seed, git SHA) for staleness, notebooks are generated from the same functions, `/api/analysis/*` is added to `scraper/serve.py`, the app moves to a top-level `app/`. The design brief got the reviewer's 11 edits (rule-based names, recorded approvals, defined Run all, data contracts, honest headline). | Reviewer: the Studio can't run or inspect steps that exist only as code strings in builder scripts. |
